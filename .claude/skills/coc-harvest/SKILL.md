# coc-harvest 收团沉淀

让语料库随团生长。**只从 timeline 正史挖**（KP 实际发出的内容），不碰草稿。

## 流程

### 1. 完整性校验

- timeline 编号连续无断号
- 当前场次闭合：最后事件应是自然的收束点（KP 确认团已收）——有疑虑先问 KP
- state.md 的"截至 #"与 timeline 最大编号一致
- `runs/<团>/raw.md` 存在且覆盖全部场次（缺失则提醒 KP：KP 终稿未归档，文风样本只能另行粘贴）。**读取纪律：按场次分节选读，不整读**

### 2. 语料沉淀（呈 KP 逐条确认后落盘）

对 timeline 逐段回看，找三类候选：

- **新技法候选**：本场出现且验证有效的叙事手法（KP 实际用过、效果好的）。按 corpus/README.md 技法条目格式写明来源场次。已有技法只是"又用了一次"的不入库
- **片段候选**：神话生物描写、仪式、时代细节等"写错即穿帮"类内容。入库前核对设定红线（与规则书/模组一致），变体 3-8 条
- **文风样本候选**：从 `runs/<团>/raw.md`（KP 终稿逐字底账，按场次节选读）中找上乘段落（开场白/检定结果/NPC对白/转场），**逐字**摘录追加到 corpus/文风锚点.md 对应 few-shot 节，标注出处场次。用途：贴合档的模仿目标与格式参照（非日常生成的文笔上限）。每类至多 2 条，宁缺毋滥

### 3. INDEX 与锚点维护

- 新条目同步更新 corpus/INDEX.md
- 若本场的 KP 措辞反馈暴露了新的风格规律（如新的过渡词），更新文风锚点的统计节

### 4. 模组修正（模组库的收团写入口）

收团时问 KP：本团发现模组哪些 bug、留下了哪些即兴发明的好细节？KP 口述 → 直接改模组库（场景卡/NPC 卡/module/routes），可标注"（<团名>修正）"。跑团中攒下的修正想法在此一并落盘；KP 本人任何时候手改模组库也合法。修正随存档点 commit——git 历史即回滚保险。

### 5. 结团标记与 git 存档点

- 整个模组完结（而非单场收束）时，在 state.md 标题行追加"（已完结）"——这是冷启动判断"未完结的团"的依据

```bash
git add campaign/ corpus/ && git commit -m "第N场存档点：<模组名>/<团名>"
```

（当前 run 的 pcs/timeline/state/recaps 与 corpus/ 的沉淀一并提交；上一场状态可在 git 历史中找回）

## 纪律

- corpus/ 只有本 skill（与 KP 本人）可写——消费者读、生产者不碰
- 技法须经验证才入库（来源可追溯），推测性的"也许好用"不入
- 理智清单：不要为了凑数沉淀；空手而收也是合法结果

## 铁律
1. 骰子和规则计算不交给 LLM
2. 走向决策归 KP——沉淀什么由 KP 终稿说话
3. 长团记忆外置——沉淀落 corpus，git 是版本史
