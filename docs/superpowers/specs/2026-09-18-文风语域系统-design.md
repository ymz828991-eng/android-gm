# 文风语域系统 设计文档

日期：2026-09-18
状态：设计定稿（KP 已批准），待实施
委托：KP 直接委托的语料建设（非收团 harvest）

## 1. 背景与问题

现行文风体系只有一个扁平的 `corpus/文风锚点.md`（单源：《不息的渴望》+《追书人》，均为西方1920s古典），consumer 装配时无条件全量加载（coc-consumer SKILL.md 装配顺序第4步"固定底座"），无任何按场合路由的机制。

运行中暴露的最大问题：**滥用散文风格——只需平白叙事或留白的地方无端煽情**。病根三处：
1. 锚点 few-shot 全是高文学性样本（月下认脸/天亮/拒信），平白叙事没有正面样本
2. consumer 生成姿态是全局"默认全力发挥"
3. 手稿类文体纪律（备忘录语言）活在记忆和 expand 实践里，不在 corpus 体系内

同时 KP 提出多场合文风需求（煽情/对白/书面/短信 × 城市/野外 × 东方/西方），并提供了 33.8 万字的他山杰作 log（《低电》，KP：萤石眼/洄音识路，美国路易斯安那沼泽小镇、现代背景）作为新语料源。

## 2. 设计总纲

### 2.1 三轴模型（本轮的核心洞察）

KP 叙述本身带**画风**。原需求中混在"场合"一列里的东西实为三个正交的轴：

| 轴 | 内容 | 性质 |
|---|---|---|
| **画风**（主轴） | 日常/白描、悬疑、温情、恐怖、侦探、魔幻、B级片、黑色幽默…… | 决定表达/结构/修辞的选择 |
| **文本形态** | 叙述、NPC对白、书面手稿、短信/电台/记录仪等现代媒介 | 文本的物理形态，跨画风存在 |
| **风味标签** | 东方/西方、城市/野外、时代 | 词汇与意象库，fragments 天然承载 |

三维都只是**索引标签**，无组合矩阵；有源才建条目（东方、侦探、魔幻等暂留空）。

### 2.2 画风替代档位

- 消费者**默认画风 = 日常/白描**（平白叙事、克制、留白优先）——KP 已裁决的 A 方案
- 画风切换仅由 KP 显式触发：意图中点名画风（"这段往黑色幽默走""温情收尾"）；场景卡如已有 KP 手写画风注记亦识别（不改 prep 的卡片格式，注记为可选自由行为）
- 原"默认全力发挥"姿态废除；原意图解析的"语气（压抑/日常/紧张）"参数废除，被画风路由吸收
- 贴合档机制不变（显式声明，few-shot 模仿）
- 同场混画风（恐怖主场+B级片减压拍）由 KP 点，条目可组合

### 2.3 协议层与审美层分界（写进锚点）

- **媒介协议层**（硬约束，全局常载）：节拍形态、单条字数、开头词表、OOC 括号分离——QQ 群媒介的物理兼容要求
- **审美层**（语域条目，按需路由）：表达、结构、修辞
- 表面机制（标点习惯、字数分布）属媒介纹理，只作备注，**永不立条目、不上条目名**

## 3. corpus 改动

### 3.1 `corpus/文风锚点.md` 瘦身重构

保留/新增：
- 媒介协议（节拍模式、过渡词表、OOC 分离）——现有内容基本不动
- 三轴模型与画风系统说明（默认日常/白描、切换规则、组合规则）
- 默认画风（日常/白描）要点 + 平白正面样本（路程压缩/火场到达/日常复位）
- 升档标杆样本小节（月下认脸/天亮/拒信等，作为抒情/温情画风的基准参照）

移除：语言风格要点中偏抒情的部分归入对应画风条目；few-shot 中高文学性样本（月下认脸/天亮/拒信等）保留在锚点的"升档标杆"小节——它们是 KP 本人手笔的画风基准，不外迁 fragments。

### 3.2 `corpus/techniques/` 新增语域条目（技法三段式：适用/做法/来源）

简短有力、高度总结、随复盘持续打磨——条目本身即"锚"。首批：

| 条目 | 层 | 来源 |
|---|---|---|
| 日常/白描（默认画风） | 画风 | 不息/追书人平白段落 |
| 经典恐怖/悬疑 | 画风 | 不息（怪物戏/揭示戏） |
| 抒情/温情 | 画风 | 追书人（天亮/日后谈） |
| 低电系（**命名待蒸馏后定**，预计黑色幽默一脉） | 画风 | 低电提取 |
| NPC 对白声部 | 文本形态 | 现有素材 + 低电 |
| 书面手稿拟真（备忘录语言纪律收编入 corpus） | 文本形态 | 记忆 + 爱憎之赘实践 |
| 现代媒介（短信/电台/行车记录仪） | 文本形态 | 低电主供 |

### 3.3 `corpus/fragments/` 收语料样本库

- 新建低电样本库：逐字摘录、按情境分组（开场电台/日常压缩/检定/对白声部/媒介/结尾收法等，以实际蒸馏为准），含红线注记（不可违背的时代/设定事实）
- 锚点中迁出的样本按画风归位

### 3.4 INDEX.md / README.md

- INDEX 技法层下加"语域"分组行
- README 写入规范补充语域条目格式说明与三轴标签约定

## 4. skill 改动

### 4.1 coc-consumer

1. 意图解析：加**画风判定**——默认日常/白描；识别 KP 点名画风；识别文本形态需求（手稿/短信/电台→对应形态条目）
2. 装配顺序：锚点（协议层）常载不变；第3步 INDEX 按需取语域条目与语料（机制已存在，补充画风路由意识）
3. 生成姿态："默认全力发挥" → "默认日常/白描画风，KP 点名时切换"
4. 自检清单加一项：**画风：本拍是否越出当前画风？**（防无端煽情的守门项）

### 4.2 coc-expand

- 手稿生成指向"书面手稿拟真"技法条目（备忘录纪律成为 corpus 正式内容）

## 5. 低电提取管线

1. **脚本分离**：解 docx（zip + w:t 正则，已验证可读）→ 按说话人标签分离（KP =【嘀嗒人】/【罔像女】前缀；滤除玩家【潜水】等）→ 产出 KP-only 工作文本（估 10-15 万字，33.8 万字总量）
2. **分块精读**（5-8 块），逐块记蒸馏笔记，按**表达（语感/句长/语域色彩）、结构（信息次序/节拍组织/蒙太奇/并置）、修辞（比喻/反讽/留白）**三层组织
3. **产物**：
   - techniques 画风条目（低电系，命名由蒸馏结果长出，不预设）+ 其他层条目中低电供给的部分（对白声部/现代媒介）
   - fragments 低电样本库（逐字，按情境分组）
4. INDEX/README 更新，git commit（注明 KP 委托语料建设）

4. INDEX/README 与实际文件一致
5. expand 生成手稿时引用书面手稿拟真条目
